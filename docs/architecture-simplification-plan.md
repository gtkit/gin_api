日期：2026-10-23。用户已批准当前分支简化方向；不创建工作树、不提交代码。

## 目标

面向个人使用 AI 维护、固定 Gin/GORM/go-redis/gtkit/logger 的业务 API，减少通用插件机制。保留当前业务能力及启动、失败回滚和关闭契约。

## 边界

- 配置直接加载与校验，先应用时区，再初始化后台资源。
- HTTP 中间件直接构造，等待最终 metrics 就绪；保留现有顺序及错误传播。
- DB/Redis/缓存/日志由具体组件构造，Runtime 显式持有关闭权。配置、中间件不再参与生命周期。
- 以固定代码顺序表达依赖；保留通知渠道的实际发送、排空和释放行为。
- 启动总预算 30 秒、单资源预算 10 秒；失败清理使用独立 30 秒预算及第二信号。HTTP/worker 分阶段关闭照旧。
- 业务 application 端口和可替换的通知渠道接口保留；不升级依赖、不修改数据库和外部 API。
- 不建立第二个通用容器或重新命名后的插件注册器。

## 实施与验收

1. 配置直接加载，保留 JWT 命令最小配置读取；按用户要求不修补 Windows 测试兼容问题。
2. 中间件直接构造，保留顺序、metrics、404/405、panic、缓存显式挂载测试。
3. 入口和 Runtime 显式装配资源，保留失败注入测试：中途失败全部回收、关闭逆序且不重复、取消预算、worker 存活时独立日志排空。
4. 删除无人使用的插件协议和注册图；更新架构检查、当前使用文档，历史验收记录不冒充当前架构。
5. build/vet/lint、受影响包 race 测试、带 scaffold 的全量测试、架构和文档引用检查。记录环境限制和基线失败，不降低现有门禁。
