# 本地认证会话管理

本能力默认关闭，只能用于 `auth.mode: local`。提供已登录修改密码及全部设备退出；不提供密码重置、短信或邮件投递。

```yaml
auth:
  mode: local
  session_lifecycle: true
```

`session_lifecycle` 为 false 或省略时，保留原有注册、登录、刷新、登出四个端点，不注册以下新接口；默认凭据查询不读取新列。`external` 模式不能开启此配置。已有私有配置无需新增字段即可维持关闭，示例配置见 `config/env.yml.example`。

## 接口

| 方法和路径 | 请求体 | 成功结果 |
|---|---|---|
| `POST /api/v1/auth/password/change` | `{"old_password":"当前密码","new_password":"新密码"}` | 当前和其他设备会话均失效，需要重新登录 |
| `POST /api/v1/auth/logout-all` | 不接受请求体 | 当前和其他设备会话均失效，需要重新登录 |

两者均须携带有效的 `Authorization: Bearer <access_token>`，兼容已有 `App-Token`。用户 ID 和会话版本仅从认证上下文取得，不允许指定目标账号。成功响应仍为统一 `code/msg/data/request_id` 信封，`data` 为 null，不返回新令牌，响应禁止缓存。

修改密码必须校验旧密码，新密码至少 8 个字符且最多 72 个 UTF-8 字节。请求体上限为 8192 字节，复用 `auth.credential` 来源限流、账号维度限流和密码运算并发容量；全部退出使用 `auth.token` 来源限流。

错误沿用现有 HTTP 约定：401 表示身份、旧密码或会话版本不可用；422 表示密码输入不合法；429 表示限流；503 表示认证依赖不可用或密码计算容量耗尽；数据库写入等未分类内部故障为 500，超时交由统一终态中间件处理。`logout-all` 携带 body 返回 400。数据库失败不返回成功，也不向客户端泄露内部原因。

现有 `/logout` 继续撤销当前访问令牌及客户端提供的刷新令牌族；只有新接口执行用户级撤销。

## 一致性与失效范围

`users.auth_version` 是持久会话版本，初始为 0。访问令牌的 `ext.session_version` 和 Redis 刷新记录的 `session_version` 使用规范十进制字符串，避免大整数精度丢失。缺少版本的原有令牌仅兼容版本 0 账号，显式非法版本拒绝。

启用后，每个受保护请求在原有账号状态查询中同时核对版本，使用与凭据写入相同的主库。JWT 验签缓存不会缓存这个判定。改密在同一条条件 UPDATE 中修改密码哈希并递增版本；条件包含用户、正常状态、旧哈希与旧版本。全部退出按用户、状态、旧版本条件递增。并发冲突返回会话失效，不能覆盖后一次更新。

登录使用密码校验时读取的版本，刷新始终保留原会话版本；因此与改密/退出交错的签发不会把旧身份升级为新版本。旧 Redis 记录按原 TTL 自然过期，无需扫描或批量删除。失效影响之后开始认证的请求，不承诺取消已进入业务处理的请求。

## 部署与回滚

1. 先审阅并通过项目既有迁移流程执行 `database/migrations/20261104000001_add_user_auth_version.sql`。不修改已执行的基线迁移。大表需在目标 MySQL 上评估 DDL 锁和上线窗口。
2. 配置保持关闭，将支持版本的程序部署到全部副本；停止向不支持版本的程序分流。
3. 确认所有副本可访问主库新列后，统一开启 `auth.session_lifecycle`。原会话在账号版本为 0 时继续可用；首次改密或全部退出后失效。

不能只关闭开关、回滚程序或删除列来恢复服务：不识别版本的程序会再次接受尚未过期的旧 JWT。安全回滚须先停止旧流量，并退役此前签名密钥或清退全部旧令牌，保证重新登录；随后才可停用功能。Down 会丢失持久撤销信息，不是独立的安全回滚操作。

当前实现附带应用、SQL 条件、JWT/刷新轮换及 HTTP 调用链测试；数据库部分使用 SQLmock，Redis 使用 miniredis。真实 MySQL 迁移、回滚、跨实例并发、DDL 锁及目标容量尚需部署环境验证，不能把本地测试当作生产准入结果。
